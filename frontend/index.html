DEPLOYMENT STAGE 1

Build the Private Origin

NovaLaunch needs a secure location for its static website. The origin must not be directly public.

🎯 Your Task

  • Create an Amazon S3 bucket.
  • Upload the NovaLaunch website files.
  • Keep Block Public Access enabled.
  • Do not enable public website hosting.

💡 Why This Matters

CloudFront will become the public entry point. The S3 origin should remain protected from direct public access.

DEPLOYMENT CHECK

Verify the Private Origin

Your S3 bucket contains the website files. Which setting should remain enabled to prevent direct public access?

DEPLOYMENT STAGE 2

Configure Global Delivery

NovaLaunch users are distributed around the world. Deliver the private S3 content with low latency without managing web servers.

🎯 Your Task

  • Create an Amazon CloudFront distribution.
  • Use your private S3 bucket as the origin.
  • Configure controlled access between CloudFront and the S3 origin.
  • Wait until the distribution is deployed.

💡 Why This Matters

CloudFront provides a globally distributed entry point while the S3 bucket remains protected as the origin.

DEPLOYMENT CHECK

Verify the Delivery Layer

Which AWS service should users reach first when requesting the NovaLaunch website?

DEPLOYMENT STAGE 3

Secure the Website with HTTPS

NovaLaunch customers must access the website over HTTPS using a trusted TLS certificate.

🎯 Your Task

  • Open AWS Certificate Manager (ACM).
  • Request a public certificate for the NovaLaunch domain.
  • Request the certificate in US East (N. Virginia).
  • Complete domain validation.
  • Associate the certificate with the CloudFront distribution.

💡 Architecture Insight

CloudFront is a global service. Certificates used for HTTPS between viewers and CloudFront must be available through ACM in the US East (N. Virginia) Region.

DEPLOYMENT CHECK

Verify the HTTPS Configuration

In which AWS Region must the ACM certificate for a CloudFront viewer HTTPS configuration be requested or imported?

DEPLOYMENT STAGE 4

Connect the Domain with DNS

NovaLaunch needs a simple way for users to reach the website using a friendly domain name.

🎯 Full Deployment

  • Open Amazon Route 53.
  • Use a hosted zone for your domain.
  • Create an Alias record pointing to the CloudFront distribution.
  • Confirm the custom domain is included in the CloudFront configuration.
  • Test the website using HTTPS.

🧪 Practice Mode

Don't own a domain? You do not need to purchase one for this learning mission. Continue using the CloudFront distribution domain and complete the DNS architecture verification below.

DEPLOYMENT CHECK

Verify the DNS Design

NovaLaunch uses Route 53 for DNS and CloudFront to deliver the website. Which Route 53 record design should direct the domain to CloudFront?
